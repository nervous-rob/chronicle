# Chronicle implementation status — contact-v1 (hearsay: memory moves between people only by telling)

## Current increment (contact-v1): the `tell` primitive and an engine-side contact phase
- `people.tell` is the only way memory moves between people: one private ledgered `tell` event plus a hearsay record in the listener at `fidelity × gossip.tell_fidelity_mult` (× `crowd_fidelity` when overheard), `source "hearsay"`, `hops+1`, `from = teller`. A better source upgrades a record; a worse one never downgrades a witness. Memory records are `{day, fidelity, source, hops, from}`.
- `people.tellable` picks ONE event the listener lacks, weighted by `[gossip.salience] × hop_decay^hops`; `people.can_remember` is the single memory-eligibility rule.
- `engine._contact_phase` runs after agency decisions and before sleep: co-presence = same place (open ground = one commons per cell at `contact.commons_mult`); rolls keyed `rng.one('contact', day, (pid<<16)|slot)`; `send_cap`/`receive_cap`; `hours_per_exchange` charged to both parties via `farming._spend(label=False)`, overhearing free; `same_household_mult` listener weight.

## Previous increment (sleep-v1a): data-driven sleep (where people sleep, what it costs, what it does to them)
- **Config tables** (`run.default.toml` `[sleep]`): scalar terms `reference_shelter` 6.0, `condition_weight` 0.5, `rest_recovery_per_quality` 0.08 (= 2× drift: one good night clears two working days, so rest only erodes under poor sleep), `shelter_need_per_quality` 1.0, `open_air_mult` by season (spring 0.5 / summer 0.7 / autumn 0.4 / winter 0.15), `wet_mult` 0.5, `ration_route_margin_hours` 0.0, `ration_refuse` false. `[sleep.access.*]` rows walked in ascending `priority`, first match wins: home (own, `shelter`, q 1.0) → household (q 1.0) → lodging (any, `lodging` affordance, rent at catalog `lodging_rate` or `Place.room_rate`, q 0.9, ledgered as a `transfer` with reason `lodging`) → outbuilding (own, `store`, q 0.6) → trespass (any, `shelter`, q 0.5, event `found_asleep`, `witness_owner`) → open (the single required `open_air` fallback, event `slept_rough`). `[sleep.consequences.*]` rows: tired (rest in [0.15, 0.4) → hours ×0.75), exhausted (rest < 0.15 → ×0.5), exposure (quality < 0.3, autumn/winter, 3 consecutive nights → health −0.1/day, cause `exposure`). `config.py` validates every field: relation vocabulary (`own|household|any`), unique priorities, exactly one open_air fallback, a draining row must name a cause, unknown fields rejected. Rules are DATA: no engine source names a building kind or a row id (asserted by the suite; a theme overlay adds a sleeping place and a consequence with zero Python changes).
- **Engine `_sleep_resolve`** (`engine.py`): once per living person per night, after agency actions and before `step_person`. Resolves the place the person stands in (off-cell or destroyed places count as none), walks the access rows, checks relation / affordance / `min_shelter`; for `rent` rows pays through `_pay_lodging` (coin lots the sleeper holds and their household owns; an unpayable rate ledgers `lodging_refused` and the walk falls through to the next row; own/household places never charge). Quality = row quality × `min(1, shelter/reference_shelter)` × `(1 − condition_weight × (1 − place.condition))`; open air = row quality × season multiplier × `wet_mult` on a wet-regime night. Emits the row's event with the sleeper as `actors[0]`; with `witness_owner` the owner's living resident household are appended so they witness and remember. Returns `(quality, rule_id)`.
- **People consequences** (`people.py`): `Person.last_sleep_quality` (float, default 1.0) and `Person.sleep_streaks` (row id → consecutive nights the row's quality/season condition held). `step_person(..., sleep_quality=, season=)`: shelter need = `min(1, q × shelter_need_per_quality)`; rest recovery = `rest_recovery_per_quality × q × age_mult`; a rest day carries no rest drift. `sleep_effects()` returns `(hours_mult, health_drain, cause, matched_rows)` — multipliers multiply across rows, drains add, cause is the last draining row's label. A death under a draining row carries that cause; starvation still wins when the nutrition cap has closed. The legacy positional `sheltered` bool maps to q 1.0/0.0 when `sleep_quality` is omitted.
- **Farming hours multiplier + ration check** (`farming.py`): `begin()` sets each living person's daily budget to `activity_hours_per_day × hours_mult` from this morning's matched rows, so tired/exhausted people plant, haul and travel less. Journey start applies the ration check: a cross-cell route longer than `hours_left + ration_route_margin_hours` means a night on the road; when `ration_refuse` is true and the traveler carries no own/household food, the journey is refused with a ledgered `journey_refused` (`reason: no_rations`, route hours and hours left recorded). Default off, because the routine remote-granary fetch exists precisely for a worker with no food in hand; turning it on is a paired before/after experiment, not a default change.
- **Agency slept packet field** (`agency.py`): observation packet `body.slept` carries last night's quality as a band only — never the number, the rule that produced it, or the rent paid.
- **Checkpoint VERSION 2** (`checkpoint.py`): serialized and validated state gains `Person.last_sleep_quality` (float in [0,1]), `Person.sleep_streaks` (keys must be configured consequence rows, values non-negative ints), `Place.condition` (float in [0,1]) and `Place.room_rate` (None or finite non-negative). Version-1 archives are rejected as schema-incompatible; no migration is provided. ## Previous increment: per-person agency interface (handoff item E)
- Added `chronicle/agency.py` (314 lines). Contract: the engine resolves consequences; a bound policy proposes **one action per person per day** from an observation packet. Packets are plain JSON: what the person physically has at hand (own carry, own intact building they stand in, own ground lots at that exact place), media physically present in the building (ownership/seal state separate), exact co-presence at the same place, own body state as **bands** not numbers, surroundings as bands/flags only, and exactly the events the person actually remembers (`agency.packet_memory_limit`, default 12). No ecological quantities, no other household's stock, no remote store counts appear in a packet (asserted).
- Action catalog `ACTIONS = rest, work, go, haul, say, note, cite, read, teach`. The menu offered in the packet is computed from physical/legal state (literacy, own medium at hand, seal state, farm assignment, reachable own places). Actions off the menu are refused **before** state is touched; the farming/people/inventory resolvers still refuse independently (e.g. hauling from a granary one is not standing in). Rejected actions cost no hours, emit zero events, and are logged with a reason. Timed social/record actions (`agency.action_hours`: say 0.25, note 1.0, cite 1.0, read 0.5, teach 2.0) are charged against the same `agriculture.activity_hours_per_day` budget as farming and travel. `work` delegates to the existing household routine; `farming.automatic` is skipped for policy-controlled people.
- Decision log: one record per agent-day with `day person packet(sha256) action ok reason hours[before,after] events[start,end] source`. Checkpointed as `agency.agents/log/day`; validated on load (known people, completed days, event spans inside the ledger, no duplicate person-day). **Policies are never serialized**: after reload every agent must be rebound (normally `ReplayPolicy` over the saved log) or unbound; stepping an unbound reloaded agent fails loudly rather than silently resting.
- `ReplayPolicy` re-executes the saved log and refuses on packet-hash divergence, log exhaustion or duplicate decisions. A resumed run reproduces the uninterrupted world fingerprint and log **exactly**, including `source` — a development bug where replay stamped `source: "replay"` onto re-executed decisions (making a resumed run distinguishable) was fixed before the final runs; the log preserves the original author.
- `TextPolicy` is the text-in/text-out seam: `complete(prompt) -> str` is supplied by the caller, the prompt carries exactly the canonical packet, JSON embedded in prose is extracted, unparsable replies become `rest` with the raw reply kept (truncated) in the log. **No LLM, network or GPU code exists in the package**; the suite exercises it with a stub.

## Previous increment: fire front correctness (handoff item A)
- `cells.py` fire now carries unfinished crossings across days: `edge_progress[cell, k]` is the completed fraction of the crossing toward neighbour k, re-priced each day at that day's edge cost (fuel, moisture, wind). A viable crossing longer than one day completes once enough burning hours accumulate.
- Explicit ignition hours are preserved (`ignite(hour=)` is validated to lie within the day). Continuing fires burn from hour 0; `burn_since_day` distinguishes new ignitions from continuing burns.
- Extinguished sources lose their progress; a target that ignites by any route clears all unfinished progress toward it, so overlapping fronts never double-ignite. Each cell gets exactly one ignition/spread event per burn episode.

## What the successful integration proves
One assigned adult household, a finite setup buffer of 15,420 ten-gram food units, two full seasons of planting/harvesting, 730 daily conservation checks and no post-setup food injection. Repeat seeds and 7/30-day reporting cadences agree. The favorable fixture explicitly holds moisture optimal and disables raids and lightning.

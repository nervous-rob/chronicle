# Chronicle implementation status — cleanup-v1 (behaviour declared by data, not Python branches)

## Increment: cleanup (capability primitives, verb registry, witness table, stage work multiplier, config-coverage gate)
- **Capability `enables` primitives + `people.can()`** (`config.py`, `people.py`): every `[capabilities.<id>]` table now lists the primitives it `enables`, drawn from the closed vocabulary `CAPABILITY_PRIMITIVES = (record, read, copy)`; `CAPABILITY_FIELDS` is the complete allowed field set (unknown fields, non-list `enables`, unknown primitives are rejected at load). `people.can(p, primitive)` answers from the enables lists of the capabilities the person holds; `_actor(pid, requires=...)` gates `record`/`read`/`copy` through it. No capability id (e.g. `literate`) is named in engine code (asserted). The default theme's `literate` enables all three; a theme capability enabling only `read` (overlay fixture `lettered`) gets the read verb but not note/cite, and `people.record` refuses.
- **`config.VERBS` registry with `_offer_`/`_do_` per verb** (`config.py`, `agency.py`): `VERBS = rest, work, go, haul, say, note, cite, read, teach`, each with `timed` (charged against `agency.action_hours`, which must define exactly the timed set) and `requires` (a primitive or None). `agency.ACTIONS = tuple(VERBS)` fixes menu order. `_menu` walks the registry calling `_offer_<verb>(**ctx)` (menu entry or None), `_resolve` dispatches to `_do_<verb>(p, a, entry)`; neither method contains a per-verb branch (asserted by source inspection), and every verb has both methods. Adding a verb is one registry row plus two methods, not edits to the menu/resolver.
- **`[events.witness]` table + `people.is_local` / `witness_scope`** (`run.default.toml`, `config.py`, `people.py`, `engine.py`): who besides the actors may remember a PUBLIC event is now data. Keys are an event type or `"type:flag"` (matches when that payload flag is `True`); values are `WITNESS_SCOPES = place | cell`; `default` is required and unknown event types or scopes are rejected. Defaults: `default = "place"`, `fire_ignited = "cell"`, `fire_spread = "cell"`, `"gathering:open_air" = "cell"`. `witness_scope(e)` resolves flag row → type row → default; `is_local(p, e)` is same cell AND (same place OR scope `cell`). `engine._witness_event` calls `is_local`; engine/people no longer name fire events in witness logic (asserted). An overlay `say = "cell"` makes a shout memorable across the cell with zero Python.
- **`development.stage_work_mult`** (`run.default.toml`, `config.py`, `people.py`): replaces the `== 'elder'` branch and `elder_work_mult` (removed from the defaults and from code). A per-stage work-day probability multiplier, all stages required, unknown stages rejected; `work_due` multiplies by the current stage's value. Defaults infant/child/youth/adult 1.0, elder 0.5 — elder works ~half as often (adult 0.63, elder 0.32 in the suite); an overlay `youth = 0.25` cuts youth work days 0.61 → 0.15.
- **`tests/test_config_coverage.py` PENDING contract** (new, 5 checks, 0.2 s): static gate over `chronicle/*.py` (config.py excluded, since it validates everything). Every section of `run.default.toml` is either READ by engine code or listed in `PENDING` with a dated reason; a pending section that quietly gains a reader fails, a pending entry that no longer exists fails, and at leaf level every key of a live section must appear as a literal in engine code unless the section is free-keyed or a vocabulary table (seasons, stages, terrains, timed verbs). Current state: 22 live sections (run, units, rng, world, transit, development, capabilities, people, needs, time, items, stance, records, weather, fire, wildlife, observation, validator, agency, events, sleep, agriculture); 21 pending (population, setup, leisure, gossip, secrets, tension, resolver, market, loans, hire, justice, succession, polity, localities, attention, chroniclers, llm, prompts, catalog, stages, transfer). Removing a section from PENDING *is* the act of wiring it in.
- **Design notes:** (1) The three mechanisms share one rule — the engine walks tables and reads fields; it never compares an id (capability, verb, event type, stage) in Python. The suite asserts this by regex over the source, which is a hygiene gate, not a proof. (2) `VERBS` lives in `config.py` as code, not TOML, deliberately: a verb needs Python resolution, so the registry is the contract between config validation (`action_hours`) and the agency module; themes add capabilities and witness rows, not verbs. (3) `events.witness` governs memory only — expectation updates for anonymous co-present people are unchanged. (4) `transfer.default_visibility` is listed pending with a TODO: inventory still hardcodes transfer visibility.
